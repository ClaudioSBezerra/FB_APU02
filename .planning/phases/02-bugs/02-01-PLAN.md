<!-- Chaves e estado relevantes do AuthContext (Phase 1 ja migrou token para sessionStorage) -->

AuthContext escreve em sessionStorage:
  - 'token'      — JWT de acesso (movido de localStorage para sessionStorage na Phase 1)
  - 'companyId'  — ID da empresa ativa (em sessionStorage)
  - 'user'       — JSON do usuario
  - 'environment', 'group', 'company', 'cnpj'

AuthContext escreve em localStorage:
  - `pref_company_${userId}` — preferencia persistente de empresa (sobrevive logout)

O interceptor global em AuthContext.tsx injeta automaticamente:
  - Authorization: Bearer {tokenRef.current}
  - X-Company-ID: {companyIdRef.current}
em TODA chamada window.fetch que nao ja tiver esses headers.

Portanto: paginas que constroem headers manualmente com localStorage.getItem('token')
e localStorage.getItem('companyId') recebem string vazia e sobrescrevem os headers
corretos do interceptor com valores vazios.

A correcao correta para paginas que so precisam de fetch autenticado:
  - Remover headers Authorization e X-Company-ID do fetch manual
  - Deixar o interceptor injetar os valores corretos a partir dos refs em memoria
  - Se a pagina precisar do companyId em logica de estado (nao apenas em headers),
    usar: const { companyId } = useAuth()
</interfaces>
</context>
