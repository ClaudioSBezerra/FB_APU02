<!-- Contrato do AuthContext que as tres paginas devem usar -->

Hook de consumo:
  import { useAuth } from '@/contexts/AuthContext'
  const { companyId, token, user } = useAuth()

companyId: string | null — ID da empresa ativa em memoria (sempre correto)
token: string | null — JWT em memoria (sempre correto, nunca ler de storage diretamente)
user: { id, email, full_name, role, trial_ends_at } | null

O interceptor global (definido em AuthContext.tsx useEffect) injeta automaticamente
em TODA chamada window.fetch:
  Authorization: Bearer {tokenRef.current}
  X-Company-ID: {companyIdRef.current}

Portanto: NÃO adicionar esses headers manualmente nos fetch calls das paginas.
Se o header ja existir no objeto init.headers, o interceptor NAO sobrescreve
(por causa do `if (!headers.has('Authorization'))`), entao remover headers manuais
garante que o interceptor sempre injeta o valor correto.

Excecao: 'Content-Type': 'application/json' deve ser mantido onde necessario
(para POST/PUT com body JSON) — o interceptor nao injeta Content-Type.

PainelApuracaoCBS e PainelApuracaoIBS:
  Antes: const token = localStorage.getItem("token") || ""
         const companyID = localStorage.getItem("company_id") || ""
         fetch(url, { headers: { Authorization: `Bearer ${token}`, "X-Company-ID": companyID } })
  
  Depois: nenhuma variavel local para token ou companyID
          fetch(url)  — o interceptor injeta os headers corretos
          Manter companyId do useAuth() somente se precisar em logica de controle (ex: para
          recarregar ao mudar empresa via useEffect([companyId]))

Managers.tsx:
  Antes: const token = localStorage.getItem('token')
         const companyId = localStorage.getItem('selectedCompanyId')
         fetch(url, { headers: { Authorization, 'X-Company-ID': companyId || '' } })
  
  Depois: nenhuma leitura de localStorage
          fetch(url)  — o interceptor injeta Authorization e X-Company-ID
          Para recarregar ao mudar empresa: const { companyId } = useAuth() + useEffect([companyId])
</interfaces>
