    LoginRL.Reset(testIP)
    for i := 0; i < 5; i++ { LoginRL.Allow(testIP) }

}

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test runner → handlers | Testes invocam handlers com db=nil — qualquer regressão que mova validação para depois do DB causará panic detectável |
| CI → backend code | Testes rodando em CI bloqueiam deploy se qualquer auth check for removido (defesa em profundidade contra regressão de SEC-04) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Spoofing | bypass de auth check | mitigate | Testes Unauthorized garantem que remover acidentalmente o `claims, ok := ...` check vira test failure imediato em CI |
| T-04-06 | Tampering | método HTTP errado aceito | mitigate | Testes MethodNotAllowed garantem que mudar acidentalmente a validação `if r.Method != http.MethodGet` quebra testes |
| T-04-07 | Denial of Service | rate limiter desabilitado | mitigate | TestRegisterHandlerRateLimited garante que RegisterRL continua aplicado; análogo do TestLoginHandlerRateLimit existente |
| T-04-08 | Information Disclosure | testes vazam segredos | accept | Bodies de teste usam strings fixas ("test@test.com", senhas dummy) — sem segredo real |
| T-04-09 | Elevation of Privilege | RefreshHandler aceita cookie inválido | mitigate | TestRefreshHandlerInvalidCookie garante que cookies sem entrada em refreshTokenStore são rejeitados |
</threat_model>
